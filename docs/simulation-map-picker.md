# 模拟定位·地图选点（1.5.4）

## 做了什么

模拟定位原来只能回放 `location-sample.json` 里的一份样本（正常来自本机采样的 Windows
定位）。现在在 **寝室打卡 → 定位来源与登录** 卡片里多了一个 **在地图上选择位置** 按钮
（只在已保存来源为 *模拟定位* 时出现）：打开一张地图，点一下就把那个点存成**命名选点**，
可以在下拉框里切换、重命名、删除。

- 地图上会画出**学校打卡点**（来自学校 `getDormitory` 返回的基准坐标与半径）、**当前生效的
  选点**与**待保存**标记。标记直接写**选点自己的名字**（例如「杏园三舍」），不再写
  「已保存（地图选点）」这种没有信息量的通用文字；保存前输入名称时，待保存标记会实时显示
  「待保存：杏园三舍」，所见即所存。
- 角标实时显示「距基准点 N 米（范围内/超出范围）」。
- **拖动平移**（按住左键拖动），滚轮或 `放大 / 缩小` 缩放，`回到学校位置` 一键复位，方向键
  平移（Shift 加快），`+/-` 缩放；`在线底图` 可关闭。
- **检测模拟定位** 现在明确报出**用的是哪个选点**：
  「模拟定位检测通过：当前使用选点「杏园三舍」，采样精度约 113 米。基于已保存位置并随机偏移，
  并非当前位置；未提交打卡。」
- **已保存的选点** 下拉框列出全部选点（含各自到基准点的距离），选中即生效；`名称` 输入框配
  `重命名` / `删除`；`保存为选点` 保存地图上当前的点。
- **同名即更新，异名即新建**：名称与已有选点相同 → 更新那个点的位置（提示写「已更新」），
  换一个名称 → 新建一个点。输入框下方直接写着这条规则。

## 定位来源卡片只留必要信息

按用户要求删掉两行纯重复的文案：选择器下方的
「保存后立即全局生效；模拟定位使用本机已保存样本，并非当前位置。重启后保留已保存的选择。」
与来源徽标「当前来源 · 模拟定位（非实时）」。它们要表达的信息在下拉框选项、检测框文案
（`模拟定位（非实时）· …`）和总览页「打卡定位来源」里都已经有了。卡片现在只剩
**选择器 → 保存定位来源 → 检测框 → 检测按钮 →（模拟模式下的地图选点）→ Windows 定位设置**，
间距仍是统一的 12 像素。

## 逻辑：列表是唯一事实来源，样本文件只是镜像

| 文件（`%LOCALAPPDATA%\yoouziauth\dorm`） | 角色 |
| --- | --- |
| `location-points.json` | **唯一事实来源**：`{"points": [{"id","name","latitude","longitude","accuracy","source","saved_at"}], "active": "<id>"}`，最多 12 个；`source` 记录它来自地图选点（`MAP_PICK`）还是本机采样（`SAMPLE`） |
| `location-sample.json` | **只是 active 那个点的镜像**。回放链路（`locate('simulation', …)`）照旧只读这一个文件 |
| ~~`location-sample.previous.json`~~ | **取消**：切换/重新选点不再破坏任何东西，因此没有"要恢复的东西" |

### 自带的默认位置

程序内置两个起始位置（`dorm_points.DEFAULT_POINTS`）：**首次运行**（store 里还没有
`location-points.json`）时把它们写进列表，第一个默认生效。

| 名称 | 坐标 | 来源 | 精度 |
| --- | --- | --- | --- |
| 李园一舍 | 29.823693, 106.422310 | `SAMPLE`（作者本机 Wi-Fi 采样） | 141 米 |
| 杏园三舍 | 29.827409, 106.422742 | `MAP_PICK`（地图选点） | 100 米 |

它们是**普通选点**：可以切换、重命名、删除，删掉之后不会自动复活。`模拟定位` 仍是 opt-in
（默认定位来源是真实定位），所以新装的程序不会自己跑到某个点上打卡。

三条约定的不变量：

1. 列表非空时，`active` 必定指向其中一个点；空列表表示"没有可用位置"。
2. 镜像永远等于 `active` 那个点；列表为空时镜像会被删除（引擎会如实报"没有可用位置"）。
3. **切换、重新选点、重命名都不会删除任何点**；只有明确的"删除"才会移除条目，而且删掉正在
   生效的点时会自动切到列表里的下一个，删掉最后一个时才明确提示"模拟定位暂无可用位置，
   自动打卡会因缺少位置而跳过"。

打开地图或执行任何选点操作时都会先**对账**（`_sync_simulation_points`）：

- 列表里没有、但磁盘上存在的样本会被**收编成选点**而不是丢掉：本机采样样本（含被手工放进
  `location-sample.json` 的旧文件）记为「本机采样样本」；1.5.2 遗留的
  `location-sample.previous.json` 记为「上一个样本」，收编后删除该遗留文件。
- 正在回放的样本优先获得 `active`（它就是程序此刻真正会提交的位置）。
- 列表与镜像不一致时以列表为准重写镜像。

### 1.5.2 的两个缺陷（本次修掉）

1. **选点逻辑会"丢点"**：1.5.2 的 `恢复上一个样本` 只把样本文件换回去，**没有更新选点列表**，
   于是列表说 A 生效、实际提交的是 B，保存过的点看起来就"没了"。根因是同一件事存了两份互相
   独立的状态；现在列表是唯一来源，镜像由列表派生，两者不可能再打架。
2. **第一次保存的点无法重命名**：`renderPoints()` 每次重绘都把名称输入框写回当前选点的名字，
   而地图瓦片是异步加载的，每加载一张就重绘一次 —— 正在输入的新名字被后台重绘冲掉，于是
   "重命名"提交的还是旧名字。现在名称框**只在生效点变化时**刷新，并有专门的回归测试盯着
   （浏览器验收里也复现了"输入后等 3.5 秒瓦片加载"的场景）。

## 坐标基准

| 数据 | 基准 | 处理 |
| --- | --- | --- |
| 地图底图（OpenStreetMap / Web Mercator） | WGS84 | 选点直接以 WGS84 保存 |
| 保存的选点 | WGS84 | 与采样样本同格式，交给原有回放链路 |
| 提交给学校的位置 | GCJ02 | 回放时由 `validate_position` 换算一次，并做既有随机偏移（3–25 米） |
| 学校基准点 | GCJ02 | 展示前用 `gcj02_to_wgs84`（三次迭代，亚米级）换算到地图坐标系 |

选点因此**不会**走第二条换算路径：它和 Windows 采样样本是同一种输入，回放仍是唯一做换算与
偏移的地方，学校看到的 payload 形状不变。

## 底图与隐私

- 底图瓦片来自 `tile.openstreetmap.org`，这是本程序**唯一**的第三方请求来源，并在
  `desktop_ui/index.html` 的 CSP 里显式列出（`img-src 'self' data: https://tile.openstreetmap.org`）；
  其余 `script/style/font/connect` 仍全部同源。关闭 `在线底图` 后不再请求任何瓦片。
- 瓦片加载失败或离线时自动退化为**离线网格 + 100 米比例尺 + 半径圈**，平移、缩放、选点、
  距离与保存全部照常工作（验收脚本把瓦片可达性单独列为一个检查项，网络抖动不会误报功能失败）。
- **署名只占一行**：`© OpenStreetMap contributors` 由画布右下角直接绘制（底图开启时显示，
  关闭后不再显示，因为此时没有第三方地图数据），原先那段"底图来自…只显示…"的长说明已按要求
  删除。OSM 的瓦片使用政策要求署名，画布角标即满足该要求。
- 页面上只在**打开地图后**、且**已保存来源为模拟定位**时显示坐标：命名选点（用户自己选择要
  提交的点）与学校公布的打卡点。**实时 Windows 定位永远不进入界面**，`snapshot()` 也仍然不含
  任何坐标或选点名称（有回归测试守着）。`simulation_map()` 在来源不是模拟定位时直接拒绝。

## 校验

- 选点保存时若学校基准点已知，就在消息里给出距离与是否在范围内；**超出半径仍然允许保存**，
  只是明确提示学校可能拒绝（学校 `verify` 仍是最终裁判）。
- 坐标非法（缺失、非数字、越界、NaN）一律拒绝，且不触碰已存样本与选点表；名称为空自动命名
  （`选点 N`），名称清洗控制字符并截断到 24 字，重名改名会被拒绝。
- 打卡进行中或定位检测进行中拒绝修改选点；来源不是模拟定位时同样拒绝。
- 选点表最多 12 个，超出时明确提示先删除；损坏的选点表按空表处理，不影响选点功能。

  遗留文件删除，镜像与生效点一致。

排查/修复记录：

1. **CSP 静默拦截瓦片**：`img-src 'self' data:` 让瓦片请求全部 `failed: csp`，界面只是"没有
   底图"。现在 CSP 显式列出底图源，并有测试保证它和模型里的 `tile_url` 主机一致。
2. **`<dialog>` 被 UA 样式限宽**：Chromium 的 UA 样式给 `dialog` 设了 `max-width`，
   `width: min(780px, 94vw)` 因此被压到 440 像素。现在显式写 `width`/`max-width`。
3. **地图无法移动**：只实现了方向键平移，鼠标没有拖动。现在支持拖动平移与滚轮缩放，并抑制
   "拖动结束那一下"被当成落点。
4. **定位来源卡片间距不一致**：`在地图上选择位置` 插在 `检测模拟定位` 与 `Windows 定位设置`
   之间时上方间距为 **0**（其他控件是 11–15 像素），选择器下方的说明文字到保存按钮也是 0。
   现在两处都是 12 像素；验收脚本会测量卡片内所有控件的间距与左右边缘，间距 < 5 像素或边缘
   不齐都会失败。
5. **选点会丢 / 无法重命名**：见上文「1.5.2 的两个缺陷」。
